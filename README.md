# CS360 – Mobile App Development Reflection

App Overview and User Needs

The goal of this project was to design and develop a functional mobile application that meets real user needs while following user-centered design principles. My app focused on inventory management, allowing users to track items, add new entries, edit existing ones, and manage their data efficiently. The main user need this app addresses is organization and quick access to inventory information without unnecessary complexity. The app was designed to be simple, reliable, and easy to navigate so users can complete tasks with minimal effort.

Screens, Features, and UI Design

To support user needs, the app included a login screen, inventory screen, add/edit item screen, and SMS permission functionality. These screens were necessary to guide the user through a clear and logical flow. The UI design focused on simplicity, readability, and usability. I paid attention to spacing, button size, and layout to make sure everything was easy to interact with on a mobile device. The design was successful because it kept the user in mind by minimizing clutter and making navigation predictable, which reduces confusion and improves overall usability.

Development Approach

My approach to coding the app became more structured throughout this course. Instead of trying to build everything at once, I broke the app down into smaller components such as UI, database operations, and logic handling. I implemented features step by step and tested them as I went. I also separated concerns where possible, which made the code easier to manage and debug. This approach can be applied in the future to any software project because it improves organization, scalability, and maintainability.

Testing and Functionality

I tested my application continuously during development by running it in the emulator and verifying each feature individually. This included testing login functionality, adding and editing inventory items, database connections, and permission handling. I also tested edge cases, such as what happens when permissions are denied. This process is important because it helps catch issues early and ensures the app behaves as expected. Testing revealed areas where improvements were needed, especially in handling user interactions and permissions more smoothly.

Challenges and Innovation

One challenge I faced was handling SMS permissions and ensuring the app responded correctly whether the user allowed or denied access. I had to adjust the logic to make sure the app remained functional in both scenarios. This required problem-solving and adapting my approach to handle different user behaviors. Overcoming this challenge helped me better understand how to build more resilient applications.

Strengths and Key Accomplishments

The component I was most successful with was integrating the UI with the backend logic, particularly connecting user actions (like button clicks) to database operations. This demonstrated my understanding of how different parts of an application work together. I also showed strong growth in structuring my code and designing with the user in mind, which are both critical skills in mobile app development.
